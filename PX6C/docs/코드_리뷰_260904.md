- 키보드 입력이 PX6C에 전달되는 경로

- 벤치 HILS 운용 안전성

실제 비행 성능이나 제어기 튜닝의 정확성은 기체 상세 제원이 업데이트된 뒤 별도로 검증해야 한다.

## 2. 종합 결론

이번 변경은 이전에 확인된 두 가지 핵심 브리지 결함을 올바른 방향으로 수정했다.

1. `MANUAL_CONTROL`의 스로틀 값을 PX4가 기대하는 `0..1000` 범위로 변환했다.
2. MANUAL 모드 요청의 `MAV_CMD_DO_SET_MODE.param2` 값을 `1`로 수정했다.

세션 단위 로깅도 키보드 입력, ARM 요청, FCC 응답, 모터 출력과 FDM 상태를 동일 시간축으로 분석할 수 있게 개선됐다. 다만 현재의 `NSH listener actuator_motors` 방식은 OFP를 수정하기 전의 임시 검증 수단으로만 사용해야 한다. 응답 구분과 직렬 링크 사용량 문제가 있어 장기적인 HILS 인터페이스로는 적합하지 않다.

## 3. 기능 단위 리뷰

### 3.1 키보드 입력 → PX6C

대상: `sim/bridge/main.py`, `sim/bridge/mavlink_link.py`, `sim/bridge/rc_source.py`

평가: 개선됨

- 브라우저 키 입력은 WebSocket 메시지로 브릿지에 도착하고 `BrowserRcSource`에 저장된다.
- 브릿지는 기본 10 Hz로 `MANUAL_CONTROL`을 전송한다.
- pitch/roll/yaw는 `-1000..1000`, throttle은 `-1..1`에서 `0..1000`으로 변환한다.
- 이는 PX4가 `MANUAL_CONTROL.z`를 내부 throttle `-1..1`로 복원하는 방식과 일치한다.
- MANUAL 모드 요청값도 PX4의 raw main mode 값인 `1`로 수정됐다.

남은 확인 사항:

- 모드 명령을 보낸 뒤 `COMMAND_ACK` 또는 HEARTBEAT의 실제 MANUAL 전환을 기다리지 않고 ARM 명령을 이어서 보낸다.
- ARM 시퀀스는 `MANUAL 전환 확인 → throttle low 확인 → ARM` 순서로 상태를 확인하는 편이 안정적이다.
- `COM_RC_IN_MODE=1`은 Joystick/MAVLink 입력 경로와 맞지만, 장비 설정을 세션 시작 시 읽어 `session.json`에 함께 기록하면 재현성이 좋아진다.

### 3.2 PX6C 모터 출력 → FDM

대상: `sim/bridge/config.py`, `sim/bridge/main.py`, `sim/bridge/mavlink_link.py`

평가: 임시 검증용으로 사용 가능, 상시 사용에는 수정 필요

현재 OFP의 `HIL_ACTUATOR_CONTROLS.controls[0..3]`이 실제 `actuator_motors`와 연결되지 않은 상황을 우회하기 위해 브릿지가 5 Hz로 다음 명령을 보낸다.

```text
listener actuator_motors
```

장점:

- OFP를 수정하지 않고 control allocator의 실제 모터 벡터를 FDM 입력으로 사용할 수 있다.
- DISARM 상태에서는 FDM 모터를 0으로 강제하고, 1초 이상 오래된 값도 폐기한다.

주요 문제:

- `SERIAL_CONTROL`로 들어오는 모든 NSH 출력에서 `control: [...]` 패턴을 찾는다. 응답이 어느 명령에서 나온 것인지 확인하지 않으므로 다른 `listener` 또는 진단 명령의 출력이 섞이면 잘못된 값을 모터 출력으로 저장할 수 있다.
- ARM 직후 여러 NSH 진단 명령을 연속 전송하고, 동시에 5 Hz 모터 프로브도 계속 전송한다. 응답 조각이 같은 버퍼에 섞일 가능성이 있다.
- HIL 센서는 같은 링크에서 250 Hz로 전송된다. 반복적인 NSH 출력은 직렬 링크와 Python 처리 시간을 사용해 HIL 센서 주기의 지연과 지터를 키울 수 있다.

권고:

1. 단기적으로 NSH 명령을 한 번에 하나만 보내고, 명령 에코부터 프롬프트까지 응답 구간을 명확히 구분한다.
2. `actuator_motors` 응답 구간에서만 `control` 배열을 파싱한다.
3. 실제 수신 주기와 HIL_SENSOR 송신 지터를 로그에 기록한다.
4. OFP의 표준 HIL actuator 매핑이 준비되면 `MOTOR_SOURCE_MODE="hil_controls"`로 복귀하고 NSH 프로브를 제거한다.

### 3.3 ARM/DISARM 및 RESET

대상: `sim/bridge/main.py`, `sim/bridge/mavlink_link.py`, `sim/bridge/config.py`

평가: 벤치 운용 목적은 타당하지만 안전 가드 필요

- ARM은 일반 안전검사를 유지한다.
- DISARM은 벤치 HILS에서 즉시 정지할 수 있도록 PX4 강제 DISARM magic number를 사용한다.
- FDM RESET 시 EKF 상태 불일치를 막기 위해 PX6C도 재부팅한다.

주의 사항:

- `REBOOT_FCC_ON_START=True`, `REBOOT_FCC_ON_RESET=True`가 기본값이므로 브릿지를 실행하거나 RESET을 누르는 것만으로 실제 PX6C가 재부팅된다.
- 강제 DISARM은 HIL 전용 설정이 확실할 때만 허용해야 한다.
- 코드가 `SYS_HITL=1`을 직접 확인한 뒤 재부팅·강제 DISARM을 허용하는 구조는 아니다.

권고:

- 자동 재부팅 기본값은 `False`로 두고 벤치 실행 옵션으로 명시적으로 활성화한다.
- 시작 시 `SYS_HITL`, `COM_RC_IN_MODE`를 읽어 예상값이 아니면 ARM과 강제 DISARM을 차단한다.
- 재부팅 전후의 FC boot time과 HEARTBEAT 복구 시간을 세션 로그에 기록한다.

### 3.4 세션 로깅

대상: `sim/bridge/session_log.py`, `sim/bridge/main.py`

평가: 분석성 크게 개선, 세션 충돌 수정 필요

세션 폴더에 다음 파일을 남기는 구조는 적절하다.

- `session.json`: 실행 환경, Git 커밋, 설정, FC 시간 매핑
- `console.log`: 브릿지와 FCC 콘솔 출력
- `events.jsonl`: ARM, 모드, ACK, STATUSTEXT, NSH 등 이벤트
- `snapshot.jsonl`: RC, 모터, FDM, 센서 상태 스냅샷
- `browser.jsonl`: 키보드/브라우저 원본 메시지
- `mavlink.tlog`: MAVLink 원본 수신 기록

문제:

- 폴더명이 초 단위이고 `os.makedirs(..., exist_ok=True)`를 사용한다. 동일 태그로 같은 초에 두 프로세스가 시작되면 서로 다른 실행 로그가 한 세션 폴더에 append된다.
- 기존 `python main.py --log bridge_debug.jsonl` 옵션은 안내만 출력하고 지정 파일을 만들지 않는다. 기존 분석 스크립트 또는 운용 절차가 조용히 깨질 수 있다.
- 콘솔 tee 버퍼에 개행 없이 남은 마지막 문자열은 종료 시 파일에 기록되지 않을 수 있다.

권고:

- 세션 이름에 millisecond, PID 또는 충돌 suffix를 추가하고 기존 폴더 재사용을 금지한다.
- `--log`는 명시적 오류로 처리하거나 호환용 통합 JSONL 파일을 생성한다.
- 종료 시 stdout/stderr tee의 미완성 버퍼를 flush한다.

시간대별 분석 시에는 다음 순서로 대조한다.

1. `browser.jsonl`에서 키 입력 또는 RC 메시지 수신 시각 확인
2. `snapshot.jsonl.rc`와 `manual_control`에서 브릿지 송신값 확인
3. `events.jsonl`에서 MANUAL 모드, ARM ACK 및 거부 사유 확인
4. `snapshot.jsonl.ofp_motors`에서 OFP 내부 모터 벡터 확인
5. `snapshot.jsonl.fdm`에서 roll/pitch/heading/alt 변화 확인

### 3.5 FDM 및 지형

대상: `sim/bridge/fdm.py`, `sim/py/world_model.py`, `sim/py/terrain_data.json`

평가: 구조적으로 개선됐으나 정량 검증은 보류

- Euler angle 직접 적분 대신 quaternion으로 자세를 적분해 큰 자세각에서의 기하학 오류를 줄였다.
- 지형, 도로와 건물 지붕을 FDM의 충돌 높이에 반영한다.
- 지상 정지 상태의 specific force를 약 `-g`로 구성해 가속도계 입력의 물리적 일관성을 개선했다.
- 지자기 벡터를 PX4의 해당 좌표 기준값과 맞췄다.

제한 사항:

- 현재 hover 구간의 yaw는 틸트 서보 차동이 필요하지만 브릿지는 `actuator_motors`만 읽으므로 yaw torque를 0으로 둔다. 따라서 현재 구성만으로 HDG 응답을 완전하게 검증할 수 없다.
- 질량, 관성, 추력, damping 및 tilt time constant는 실제 기체 확정값이 아니다.
- 단순 지면 충돌과 속도 강제 0 처리는 접촉 역학이나 착륙장치 모델을 대신하는 근사치다.

실제 기체 정보가 업데이트되면 다음 순서로 보정해야 한다.

1. 모터별 명령-추력 곡선과 회전 방향
2. 기체 질량, 무게중심, 관성모멘트
3. 모터 위치와 실제 control allocation 행렬
4. 틸트 서보 각도·속도·지연 및 yaw 생성 모델
5. 공력 감쇠와 전진비행 모델

## 4. 수정 우선순위

### 우선순위 1 — 신뢰 가능한 모터 피드백

- NSH 응답 직렬화 및 명령별 파싱
- 모터값 source와 age를 각 snapshot에 기록
- HIL 센서 주기 지터 측정

### 우선순위 2 — 세션 로그 격리

- 동일 시각 실행 시 폴더 충돌 방지
- 기존 `--log` 운용 절차의 호환 정책 결정
- 종료 시 로그 버퍼 완전 flush

### 우선순위 3 — 벤치 안전 가드

- `SYS_HITL`과 `COM_RC_IN_MODE` 사전 확인
- 자동 재부팅 및 강제 DISARM 명시적 활성화
- MANUAL 모드 전환 확인 후 ARM

### 우선순위 4 — 실제 기체 데이터 반영

- 실제 제원이 들어오기 전에는 현재 FDM을 인터페이스와 폐루프 구조 검증용으로만 사용한다.
- 실제 제원 반영 후 hover, roll/pitch step, yaw/tilt 전환, 고도 응답을 다시 검증한다.

## 5. 권장 합격 기준

현재 단계에서 다음 조건을 만족하면 “OFP 수정 전 SIM 연동 검증”은 통과한 것으로 볼 수 있다.

- 키 입력 후 200 ms 이내에 `manual_control` 로그가 바뀐다.
- PX6C가 MANUAL 모드와 ARMED 상태임이 HEARTBEAT/이벤트에 기록된다.
- throttle 변화 후 유효한 최신 `ofp_motors` 4개 값이 기록된다.
- DISARM 시 FDM 입력 모터가 즉시 0이 된다.
- 모터 변화 이후 FDM의 altitude 및 roll/pitch 변화가 같은 세션 시간축에 기록된다.
- NSH 프로브 사용 중에도 HIL_SENSOR 송신률과 FCC 링크가 허용 범위 내에서 유지된다.
- 동일 실행을 별도 세션 로그만으로 재현·분석할 수 있다.

HDG/yaw 동특성 및 실제 비행 성능은 틸트 서보 출력과 실제 기체 제원이 추가된 뒤의 별도 합격 항목으로 둔다.
